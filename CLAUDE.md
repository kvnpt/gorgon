# CLAUDE.md — Gorgon

Byzantine chant notation writer. Live at `gorgon.orthodoxy.au`.

## Stack

- Vanilla JS, no build step, no framework
- Express server (serves static + SBMuFL API)
- Neanes font (WOFF2, GPL-3.0, SBMuFL PUA-mapped glyphs)
- 375 glyphs from SBMuFL spec (`data/sbmufl/`)
- Cloudflare Worker with static assets (`worker.js` + `wrangler.jsonc`): `public/` served as assets, `/api/*` and `/health` from bundled `data/` JSON. Deploys automatically on push to `main` (`.github/workflows/deploy.yml`, needs repo secret `CLOUDFLARE_API_TOKEN`); manual: `npm run cf:deploy`
- Legacy: Docker on hades (`server.js`), Caddy reverse proxy. Keep `server.js` and `worker.js` API routes in sync

## Architecture

- Score = array of elements (neume, martyria, rest, linebreak, spacer). A rest (`{type:'rest', glyph:'leimma1'..'leimma4'}`) is a leimma, an empty beat of its own: the Signs drawer inserts it after the focused note (or in place of a pending Ison), and swipes step it from 1 to 4 beats
- Each neume references an SBMuFL glyph name + codepoint
- Rendering: font glyphs in PUA range via `font-family: 'Neanes'`. Every neume in the score keeps the same room below it (marks or not), so a line's neumes share one baseline (the oligon line) and syllables line up; don't add per-note bottom padding
- Palette organised by SBMuFL ranges (13 categories → 6 tabs)
- Compose pad (thumb zone): focus is a symbol or an empty slot. One vertical swipe = exactly one increment (no dial). Moving into a blank spot (committing the last symbol, tapping a gap, loading) puts a pending Ison there (`placeholderEl`: drawn in the accent orange, not saved, not printed, dropped if you leave backwards; it becomes real once changed or committed). In martyria mode the pending symbol is the first martyria option. Del on it acts as backspace. Del never drops words (`deleteKeepingWords`/`pushWordsOn`): a deleted note's syllable moves on to the next note, pushing the words along to the first note without a syllable of its own (not the pending one), or past the last note. Words past the last note are kept in `score.lyricTail`, drawn after the score as grey italic syllables without symbols (editor only, not printed), and flow onto wordless notes written at the end (`flowLyricTail`, run in `reanalyze`); lyric mode reads and writes them too. On a note, swipe up/down steps its interval (`neume-values.json`). Swipe right/left changes its time in every mode (`onSwipe`): right lengthens by a beat, left shortens, on the same `timeStep` ladder as Quant.; where the focus has a combinable pair (`pairAtFocus`, the one the Combine pill shows), the first swipe left combines it instead. On a rest it steps the beats; on a martyria or a blank spot it moves (right commits, left goes back). Tap on a symbol, or the small Next arrow on the pad's right edge, commits and moves on; the unlabelled arrow on the left edge goes back. A long press on the pad switches to Qual. for one note (purple: the pad glyph and the selected note, `qual-preview`; `qualOnce`), and the next commit switches it off; Qual. turned on with its button stays on until tapped off (Kevin: to do all the quality signs in one go). Mart. always goes off after one martyria
- Pad modes (corner toggles, one at a time; `padMode`): with none on (the default, `'quantity'`) swipes step the interval. Quant. top-left (`'time'`: swipe up lengthens the note by a beat (klasma, then apli (the dot under the note, e.g. apostrophos + antikenoma + apli), dipli, tripli, tetrapli) and swipe down shortens it (gorgon, digorgon, trigorgon), one ladder per note from `timeOptions`, filtered by the `timeReplacements`/`gorgonReplacements` rules; a klasma goes below on neumes with a crowded top), Qual. top-right (swipes cycle the note's quality sign `vocalExpression`: none, psifiston, vareia, omalon, antikenoma, heteron, endofonon, filtered by `qualityAllowed` from `neume-combinations.json`), Mart. bottom-left (switches itself off once a martyria is committed). Quality signs draw inline with the neume (`neumeRun`): vareia before it, the zero-width marks after it
- Combined neumes (`focusPairs` in `app.js`), mostly so one syllable can sit over two notes: only around the note in focus (with the note before it and the one after it; on a blank spot, the pair just finished), a small orange mark over the join shows the combined glyph, also in lyric mode (focus follows the caret), and the pad shows a Combine pill (bottom-right) for the pair ending on the focus, else the one starting there; a tap swaps the pair for the one neume. Rules: apostrophos + apostrophos → running elaphron (a gorgon on the first is built in; the second note's time sign moves onto it); oligon + oligon → kentemata on top of the oligon (`KentemataPlusOligon`), or underneath (`OligonPlusKentemata`) when the second oligon has a gorgon; ison / apostrophos / elaphron / elaphron+apostrophos / hamili + oligon → that sign and kentemata on the oligon "table". A syllable on the second note moves to the next note, pushing the words on up to the first note without a syllable of its own (blank or a hold, which is replaced; with none, past the last note into `lyricTail`). Not offered when the second note has other signs or a time sign the combined neume can't take. Hidden in print
- Qual. ladder also holds Petasti: none, petasti (an ascending oligon-family neume swapped for the petasti of the same interval, `petastiFormOf`/`oligonFormOf`), then the quality signs. Lyric Hold inserts `_` after a selected syllable (holds it over the next note, pushing the rest on) instead of replacing it
- Martyria mode (pad's bottom-left toggle): the empty slot inserts martyriae instead, and swipes on a martyria cycle its options: the reached pitch (auto) first, then the mode's base notes from `mode-keys.json`, then the rest by distance. A martyria renders as note letter + zero-width root sign (`martyria-rules.json` via `computeMartyria`); an explicit one (`auto:false, noteValue`) sets the pitch
- Title, subtitle and mode are set on the page itself (`#score-head`, outside the re-rendered `#score-body`): the title is a textarea styled as the heading; an optional subtitle (`metadata.subtitle`, e.g. the feast) sits left of the mode on one line, greyed "Subtitle" when empty and hidden in print; the mode line opens a popmenu (after agora's) with authentic modes 1–4 beside their plagals 5–8. No toolbar
- Palette is hidden behind the Signs button; supporting neumes (gorgon, klasma) attach to the focused base neume. Zero-width signs (marks: time, quality, fthores, accidentals) are shown on an Ison in the palette (`isMarkGlyph` measures the font), since Safari draws a lone mark as nothing
- Lyric mode (`public/lyrics.js`; Lyric button, Enter, or a second tap on the selected note; `tapNote`): the first tap on a symbol only selects it, wherever on it you tap. A quick double tap is caught on `touchend` (`initDoubleTap`) so iOS doesn't zoom, and opens lyrics. One text field, kept outside the re-rendered score so the phone keyboard stays up, holds the words from a start note on; every change re-lays them one syllable per note. Space = next word/note, `-` hand break (a word with any `-` is split only there; big hyphen button), `_` holds a syllable over one more note (Hold button; shown as `-` inside a word, extender line after one), `~` joins words on one note. Auto-split: Greek by grammar rules (diphthongs, word-initial clusters), English via Hypher + TeX en-US patterns (`public/vendor/`) with a vowel-group fallback and a church-word exception list. A note's lyric stays a string (`Ky-`, `-`, `_`); `buildLyricText` rebuilds the text from them
- Transcription mode (Scan button, `scan.js`): a scan (photos or PDF) is cut into its lines (ink profile per pixel row, period by autocorrelation, cuts at low points by dynamic programming; the cutter sheet lets you drag/tap/add cuts), and each line shows above the notes written for it. Writing that climbs or falls across the page (or a tilted photo) is followed: `detectLines` takes the rows along the slant that makes them sharpest for each stretch of the page (`pages[i].skew`, points of `[y, dy/dx]`, read with `skewAt`), a cut is a slanted line kept as where it crosses the middle of the page, and a line with `skew` is drawn level in its strip (CSS `skewY`) and sent level to the reader (`lineJpeg`). The cutter's "Find the lines again" recuts a scan from its pictures (for scans made before this, or after a bad start). `score.scan = {pages:[{id,w,h,skew?}], lines:[{page,y0,y1,skew?}]}`; a `{type:'scanline', line:k}` element marks where line k starts (draws nothing when the scan is hidden, in print or on a share link; Del never removes it, the arrows under a strip move it one note; Next at the end of a line opens a blank spot there instead of jumping to the next line). The pictures stay in this browser's IndexedDB (other devices show blank strips). Heading lines (above the first band whose ink spans most of the width) get no notes when a scan is laid over an existing score. Read with Claude (signed in, `lib/read.js`): each empty line of music has a Read button, and the Scan sheet reads all empty lines in turn; lines of the same score written by hand, or read and then checked, go along as examples (up to two, nearest first). A line Claude filled is `by:'claude'` and shows a Checked button; tapping it clears the line's tints and makes it `by:'checked'`, an example for the lines read next. On a score with nothing written yet, Read all reads only the first line, so it can be set right and checked before the rest. Notes Claude was unsure of carry `unsure:true` (tinted, editor only) until committed with Next. A martyria read from the scan keeps the note its letter names (`scan:'di'`): `analysis.js` sets the pitch to that note nearest the one the notes reached and marks the entry `off` when they differ, and the editor tints it and says so on the line's strip (`scanChecks`), since a step before it must be wrong; Next on it makes it an ordinary explicit martyria. Pages are kept up to 2400 px wide (the reader takes 2576). What Claude answered for a line is kept as `lines[k].read` (rows of `[kind, neume, note, time, gorgon, quality, lyric, unsure]`), so the corrections made after can be measured against it; each call's token usage goes to D1 `read_log`, so the real cost per line is known. The Worker bundles npm deps, so the deploy workflow runs `npm ci` first
- Auto-save to localStorage every 5s (`gorgon-score-v2`). Each score has `metadata.id`
- Accounts (optional): Gorgon shares agora's Cloudflare Access application (team `agora-admin.cloudflareaccess.com`), which already covers `/admin` and `/api/admin/*` on every *.orthodoxy.au host, so one login works across the domain's tools. Sign in is `/admin?back=<path>`, and the account API lives under `/api/admin/` for that reason. `ACCESS_AUD` (that app's audience tag) is in `wrangler.jsonc` vars; empty = sign-in hidden. Signed in, the open score is also PUT to D1 (`gorgon` database, one row per email + doc id) every 5s when changed. Signing in never replaces anything: the visitor's score joins the account as its own document. A write based on an older version gets 409 and the browser keeps its version as a separate copy
- Share links (Share button, signed in only): `/s/<token>` opens the same app shell read only (`viewOnly` in `app.js`, `body.view-mode`): no pad, no insert points, nothing written to `gorgon-score-v2`; A−/A+ text size (`zoom` on `#score-body` via `--view-zoom`, `initTextSize`, remembered in `gorgon-view-zoom`; the editor has its own A−/A+ in the score's top-right corner, remembered in `gorgon-edit-zoom`, since its header is full); a PDF button (`window.print()`, as in the editor); keeps the screen awake. The link reads the account's copy live (D1 `shares` table: token → email + doc id), so later fixes reach readers; Stop sharing or deleting the score kills it. Link previews: a shared score's preview says nothing about Gorgon (Kevin): `og:title` is the score's title, `og:description` its subtitle · mode, and `og:image` a 1200×630 PNG of the title and the first notes with their words, drawn by the editor on a canvas (`previewImage` in `app.js`) and PUT to `/api/admin/documents/:id/preview` (D1 `previews` table) when the score is shared and what it shows changed (`sendPreview` in `account.js`; the document PUT answers `shared`). Served at `/s/<token>/preview.png`. "Edit a copy" goes to `/?copy=<token>`: the editor opens the shared score under a new id (asking first if an unsaved score would be replaced). Kevin's line "Gorgon — quick notation for the Byzi chanter" is the home page's `og:title` only (`index.html`; the Worker removes it on `/s/`). `index.html` uses absolute `/app.css` `/app.js` so it works under `/s/`
